# TG multi-account MCP

[English documentation](README.md)

Приватный MCP-сервер для нескольких Telegram-аккаунтов и нескольких опциональных ботов. Владелец запускает сервис, открывает веб-страницу, добавляет аккаунты по QR и при необходимости вводит пароль Telegram 2FA. Подключённые агенты читают облачную историю и отправляют текст через явно выбранный `account_id` или `bot_id`.

Главный MCP-токен имеет полный доступ. Через `create_agent_token` можно выдать отдельному агенту только чтение или отправку и ограничить его конкретными аккаунтами, ботами и чатами. Содержимое Telegram считается недоверенными данными. Сервер не отправляет сообщения сам: вызов инструмента отправки должен быть разрешён пользователем.

Это неофициальная интеграция на базе Telegram API, не связанная с Telegram и не одобренная им.

Оператор обязан соблюдать [условия Telegram API](https://core.telegram.org/api/terms) и [условия лицензирования контента](https://telegram.org/tos/content-licensing): использовать собственный `api_id`, не выполнять действия без ведома и согласия владельца аккаунта и не передавать контент Telegram AI/ML-системам без явного, информированного, утвердительного и продолжающегося согласия всех затронутых пользователей для конкретного контента и контекста. Установка сервера не даёт прав на чужие сообщения или файлы.

## Локальный запуск

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```sh
uv sync --frozen
uv run tg-mcp setup
TG_MCP_PORT=8765 uv run tg-mcp serve
```

`setup` один раз запрашивает собственные Telegram `api_id` и `api_hash` и генерирует MCP-токен. После запуска откройте [http://127.0.0.1:8765/](http://127.0.0.1:8765/). Для сервиса, привязанного к loopback, локальная страница настройки доступна без токена. Мастер сначала показывает QR для **Telegram → Настройки → Устройства → Подключить устройство**, затем при необходимости просит пароль 2FA и на последнем шаге — имя аккаунта. Просроченный QR обновится автоматически; незавершённый шаг 2FA через 5 минут также сбросится на свежий QR. Можно добавить второй и последующие аккаунты тем же способом.

Панель показывает состояние идентичностей, график использования, историю операций и статистику по аккаунтам. История хранится в `operations.json` в приватном каталоге состояния и ограничена последними 2000 событиями. В ней есть только тип операции, выбранный identity, chat ID, результат и длительность. Тексты сообщений, поисковые запросы, токены и пароли в аналитику не попадают.

Бот необязателен. Создайте его через [BotFather](https://t.me/BotFather), затем добавьте имя и токен в отдельном разделе страницы. Токен проверяется методом `getMe` до сохранения. Сервер не вызывает `getUpdates`, не меняет webhook и не читает через бота историю пользовательских аккаунтов.

Состояние по умолчанию хранится в `~/.local/share/tg-mcp`. Другой каталог задаётся параметром `--state-dir` либо `TG_MCP_STATE_DIR`. Получить общий токен для MCP-клиента:

```sh
uv run tg-mcp show-token
```

## Подключение агента

URL Streamable HTTP — `/mcp`; каждый запрос требует Bearer-токен:

```json
{
  "url": "http://127.0.0.1:8765/mcp",
  "headers": {
    "Authorization": "Bearer <MCP_TOKEN>"
  }
}
```

Это пример параметров, а расположение полей зависит от MCP-клиента. OAuth-only клиенты без возможности задать Bearer-заголовок не поддерживаются.

### Плагин для Codex

В репозитории есть плагин Codex с автоматическим защищённым поиском MCP-сервиса и инструкциями для

export TG_MCP_TOKEN="$(uv run tg-mcp show-token)"

Сервер никогда не выбирает первый аккаунт автоматически и не переключает отправителя после ошибки. Числовые `chat_id`, ID сообщений и `reply_to` передаются строками, например `"-1001234567890"`. Получайте ID через `list_chats` или `find_chats`; поиск сопоставляет слова независимо от порядка, устойчив к распространённым русским окончаниям и понимает транслитерацию между кириллицей и латиницей. `date_from` и `date_to` задаются в формате `YYYY-MM-DD`, обе границы включительны. `limit` — от 1 до 100, продолжение — `next_cursor`. Курсор связан с аккаунтом, чатом, поисковым запросом и диапазоном дат.

Глобальные выборки ограничены первыми 10 000 результатами. `list_attachments` принимает `media_kind`: `any`, `photo`, `video`, `voice`, `audio` или `document`. При поиске всех типов одна страница сканирует не более 2 000 сообщений и при необходимости возвращает продолжение. `get_message_context` принимает до 50 сообщений с каждой стороны. `resolve_message_link` не открывает произвольные URL и принимает только ссылки `t.me`/`telegram.me`.

`get_folder_messages` принимает ID или имя папки без учёта регистра, объединяет до 100 чатов и сортирует результат по времени. Одна выборка ограничена 500 сообщениями и продолжает чтение через подписанный `next_cursor`. Для запроса «сообщения за сегодня в папке ITQ» агент сначала вызывает `list_folders`, затем `get_folder_messages` с одинаковыми `date_from` и `date_to` и IANA `timezone_name`, например `Europe/Madrid`; определение задач выполняет сам агент по возвращённому контексту.

Отправка принимает обычный текст до 4096 UTF-16 единиц и необязательный `reply_to`. Markdown/HTML не интерпретируются, предпросмотр ссылок отключён. Вызов успешной отправки возвращает фактические `sender_id`, `chat_id` и `message_id`. При повторе сетевого запроса передавайте тот же `idempotency_key`: сервер сохранит подтверждённый результат и не отправит сообщение второй раз. Один ключ нельзя использовать с другими аргументами.

Черновики лежат в приватном `drafts.json`, поэтому их текст доступен только процессу сервера и токенам с подходящими правами. `send_draft` запоминает успешный receipt и при повторном вызове возвращает его без новой отправки. `poll_updates` хранит последние 2000 событий только в памяти процесса; после перезапуска агент начинает с нового курсора.

`send_attachment` принимает источник внутри Telegram (`source_chat_id` и `source_message_id`) и отправляет его в выбранный чат без доступа к произвольным локальным файлам сервера. `forward_messages` сохраняет отметку пересылки. Эти операции доступны для пользовательских аккаунтов; бот продолжает отправлять текст через `send_as_bot`. Передача `emoji: null` в `react_to_message` удаляет реакцию текущего аккаунта.

`download_attachment` возвращает JPEG, PNG, GIF и WebP до 10 МБ как MCP image-блок. Остальные небольшие вложения возвращаются как бинарный embedded resource с MIME-типом и именем файла. Для файлов больше 10 МБ агент последовательно вызывает `download_attachment_chunk`, передавая полученный `next_offset`; размер одного чанка ограничен 4 МБ. Общего лимита со стороны MCP-сервера нет: доступен любой файл, который уже принят Telegram (сейчас до 4 ГБ). Временные файлы не создаются.

## Несколько идентичностей и токены агентов

Каждый пользовательский аккаунт имеет стабильный случайный ID `acct_…` и отдельный файл Telethon-сессии. Каждый бот имеет `bot_…`. Имена можно менять, идентичность можно отключить и снова включить без удаления сессии. После QR/2FA мастер запрашивает имя; только завершённая запись начинает работать в MCP без перезапуска.

Состояния аккаунта:

- `waiting_qr` — QR готов к сканированию;
- `waiting_2fa` — нужен пароль Telegram;
- `waiting_name` — Telegram-вход завершён, нужно задать имя;
- `ready` — аккаунт доступен MCP;
- `revoked` — сохранённая сессия больше не авторизована, запросите новый QR;
- `error` — ошибка относится только к этой записи;
- `disabled` — идентичность вручную отключена.

Один Telegram user ID нельзя добавить дважды. Если один аккаунт недоступен, HTTP-сервис, другие аккаунты и боты продолжают работать.

`create_agent_token` возвращает секрет только один раз; на диске хранится SHA-256 hash. Scopes: `read`, `send`, `admin`. Необязательные `identity_ids` и `chat_ids` сужают доступ. Пустой список запрещает все identities или чаты, а `null` не накладывает ограничение. Токен с ограниченным списком чатов использует адресные инструменты с явным `chat_id`; агрегатные инструменты вроде общего поиска, папок и inbox для него закрыты, чтобы не раскрыть соседние чаты. Главный токен из `credentials.json` остаётся полным административным ключом. Отзыв через `revoke_agent_token` действует со следующего HTTP-запроса.

Старое состояние с `account.session` мигрируется при первом запуске в отдельную запись `Primary`. Прежний одиночный bot token также становится записью `Primary bot`. Миграция копирует сессию до атомарной публикации каталога; исходный файл удаляется только после успеха.

## Развёртывание через Docker Compose

Нужны Docker Engine с Compose, домен с A/AAAA-записью на сервер и открытые TCP 80/443.

```sh
cp .env.example .env
# Укажите TG_MCP_DOMAIN=mcp.example.com
docker compose build
docker compose run --rm --no-deps tg-mcp setup
docker compose up -d
```

Откройте `https://mcp.example.com/#token=<MCP_TOKEN>`. URL-фрагмент не отправляется серверу: страница удалит его из адресной строки и будет держать токен только в памяти вкладки. Можно также открыть `/` и ввести токен вручную. На удалённом сервере список аккаунтов, QR и setup API без правильного Bearer-токена не возвращаются.

Caddy публикует `/`, `/setup/api/*` и `/mcp` по HTTPS. Внутренний порт приложения наружу не открыт. Контейнер работает непривилегированным пользователем, с read-only root filesystem и одним worker. Запускать несколько реплик с одним томом состояния нельзя.

После настройки агенты подключаются к:

```text
https://mcp.example.com/mcp
```

## Безопасность и эксплуатация

Каталог состояния имеет права 0700, файлы — 0600. Симлинки, hardlink-файлы, чужой владелец и более широкие права отклоняются. Сессии Telegram фактически дают доступ к аккаунтам; резервную копию делайте при остановленном сервисе и храните зашифрованной. Не выполняйте `docker compose down -v`, если хотите сохранить авторизацию.

Веб-оболочка `/` и её явно разрешённые локальные файлы `/assets/*` публичны и не содержат данных аккаунтов. `/setup/api/*` требует тот же Bearer-токен, кроме loopback-bound процесса при обращении с loopback-клиента. Host и Origin проверяются по точному allowlist. Страница не загружает внешние скрипты, стили, шрифты или аналитику и получает CSP, `no-store`, `no-referrer` и запрет встраивания.

Логи не содержат текст сообщений, токены, QR URL, 2FA-пароли и Telegram RPC. Зависимые библиотеки работают без подробных production-логов. Ошибки инструментов очищены от входных данных и upstream exception text.

Основные коды ошибок:

- `identity_not_found`, `identity_disabled`, `not_authorized`, `unavailable` — состояние выбранного ID;
- `rate_limited` — Telegram просит подождать, иногда с `retry_after_seconds`;
- `delivery_unknown` — сообщение могло уйти до сетевого сбоя; проверьте историю выбранного аккаунта и не повторяйте вслепую;
- `sender_mismatch` — Telegram отправил с identity чата, например при анонимном администрировании;
- `forbidden`, `invalid_request`, `invalid_cursor` — права, параметры или контекст курсора не подходят;
- `idempotency_conflict` — ключ повторной отправки уже использован с другими аргументами;
- `folder_not_found`, `draft_not_found`, `agent_not_found` — запрошенная локальная или Telegram-сущность отсутствует.

Для ротации общего MCP-токена остановите приложение:

```sh
docker compose stop tg-mcp
docker compose run --rm --no-deps tg-mcp rotate-token
docker compose run --rm --no-deps tg-mcp show-token
docker compose up -d tg-mcp
```

Старый токен и подписанные им курсоры перестанут работать. При утечке дополнительно отзовите пользовательские сессии в Telegram Devices и замените bot token через BotFather.

Переменные сервера: `TG_MCP_BIND`, `TG_MCP_PORT`, `TG_MCP_STATE_DIR`, `TG_MCP_ALLOWED_HOSTS`,
`TG_MCP_ALLOWED_ORIGINS`, `TG_MCP_DISCOVERY`, `TG_MCP_DISCOVERY_PORT` и
`TG_MCP_DISCOVERY_URL`. Allowlist задаются через запятую, wildcard запрещён. Для публичного
доступа используйте HTTPS-прокси из Compose.

## Ограничения и проверка

Не поддерживаются секретные чаты, удаление обычных сообщений и распределённое развёртывание. История читается напрямую из Telegram по запросу и не копируется в локальную базу. Диалоги используют позиционную пагинацию, поэтому при новых сообщениях между страницами возможны повторы или пропуски.

Проверки разработки:

```sh
uv run ruff check .
uv run ruff format --check .
uv run pytest -q
uv build
TG_MCP_DOMAIN=mcp.example.test docker compose config --quiet
docker build -t tg-account-mcp:local .
```

Автоматические тесты используют поддельные Telegram-адаптеры и настоящий MCP SDK поверх локального HTTP. Они не отправляют реальные сообщения. Живую отправку выполняйте только в явно выбранный тестовый чат.
