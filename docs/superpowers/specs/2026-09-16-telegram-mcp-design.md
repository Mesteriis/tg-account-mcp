# Telegram MCP: сервер с доступом по токену

Статус: исходная однопользовательская спецификация. Реализация расширена согласованным документом `2026-09-16-multi-account-web-onboarding-design.md`: настройка выполняется на веб-странице, поддерживаются несколько аккаунтов и ботов, а каждый MCP-вызов явно выбирает `account_id` или `bot_id`.

## Назначение

Один владелец подключает свой Telegram-аккаунт по QR и одного существующего бота по токену BotFather. Несколько авторизованных агентов подключаются к одному MCP-серверу, читают доступные аккаунту облачные чаты и отправляют текстовые сообщения от пользователя или бота.

## Развёртывание и доступ

- Python, Telethon для пользовательского MTProto API, официальный Python SDK MCP и HTTP-клиент для Bot API. Точные совместимые версии фиксируются при реализации после проверки API.
- Один процесс приложения владеет Telegram-сессией. Не запускать несколько рабочих процессов с одним файлом сессии.
- Транспорт MCP — Streamable HTTP, маршрут `/mcp`, за обратным прокси с HTTPS. Внутренний порт приложения не публикуется в интернет.
- Каждый запрос MCP требует `Authorization: Bearer <token>`. Сервер не предоставляет анонимный доступ к инструментам, ресурсам или Telegram-сессии. Авторизация проверяется и на последующих запросах установленной MCP-сессии.
- В первой версии один общий случайный токен доступа с не менее чем 256 битами энтропии. Его замена и перезапуск сервера отзывают прежний доступ. Все владельцы токена имеют одинаковые права чтения и отправки.
- Клиент агента должен поддерживать Streamable HTTP и передачу заголовка Authorization. Поддержка клиентов, требующих OAuth, не входит в первую версию.
- Принимаются только настроенные Host и, если присутствует, Origin. Значения задаются для конкретного развёртывания.

## Первичная настройка владельцем

1. Владелец получает Telegram `api_id` и `api_hash` и задаёт их на сервере.
2. Через административную CLI по SSH запускает вход. CLI показывает QR в терминале, обновляет его после истечения срока и позволяет отменить операцию.
3. Владелец сканирует QR приложением Telegram. При включённой 2FA вводит пароль в скрытом поле терминала; пароль не сохраняется.
4. Отдельно вводит токен бота через скрытый ввод; сервер проверяет его методом `getMe`.
5. После сохранения настроек запускает сервис и подключает агенты, указав HTTPS URL и MCP-токен.

Настройка и рабочий сервис не используют файл Telegram-сессии одновременно: CLI и сервис удерживают общий эксклюзивный файловый замок. Повторная авторизация выполняется при остановленном сервисе. MCP-инструменты не принимают пароли, токены или команды смены аккаунта. Административная веб-панель в первую версию не входит.

## Инструменты

- `get_status`: состояние подключения пользователя и бота, без секретов.
- `list_chats`: список чатов аккаунта с ограничением размера страницы и продолжением.
- `get_chat_history`: история выбранного чата с ограничением размера страницы и продолжением.
- `search_messages`: поиск текста внутри выбранного чата с пагинацией.
- `send_as_user`: отправка текста в указанный чат через пользовательский аккаунт, необязательный ответ на сообщение.
- `send_as_bot`: отправка текста через Bot API, необязательный ответ на сообщение.

Отправитель всегда определяется именем инструмента. Переключение на другого отправителя при ошибке запрещено. Ответ при успешной отправке содержит фактического отправителя, чат и ID сообщения. Числовые Telegram ID передаются в MCP как десятичные строки. Параметры и длина сообщений валидируются до вызова Telegram.

## Данные и ошибки

Сессия и секреты сохраняются в отдельном постоянном каталоге с правами владельца (каталог 0700, файлы 0600), исключённом из Git и образа контейнера. Журналы не содержат текстов сообщений, QR-токенов, Telegram-сессии, паролей или заголовков авторизации. Полная история чатов не копируется в локальную базу: страницы запрашиваются по требованию.

Ошибки различают отсутствие авторизации, недоступный чат, отсутствие прав, ограничения частоты и сетевую неопределённость. При ограничении Telegram возвращается время ожидания. Отправка с неизвестным результатом после сетевого сбоя не повторяется автоматически: клиент получает явное предупреждение, что сообщение могло быть доставлено. Для пользовательских отправок используются предусмотренные MTProto идентификаторы запросов; Bot API не считается обеспечивающим идемпотентность повторной отправки.

## Границы первой версии

История читается с правами пользовательского аккаунта. Бот пишет только туда, куда разрешает Telegram; добавление бота не предоставляет ему доступ к личным чатам владельца. Секретные чаты, загрузка вложений, редактирование и удаление сообщений, массовые рассылки, несколько владельцев и распределённое развёртывание не входят в первую версию.

## Проверки и поставка

- Регрессионные тесты: истечение QR, запрос 2FA, восстановление и отзыв сессии, пагинация, валидация параметров, разделение отправителей, ограничения частоты и неопределённый результат отправки.
- Проверки HTTP: отсутствие и неверный токен, авторизация всех MCP-запросов, недопустимые Host/Origin, отсутствие секретов в ответах и журнале.
- Интеграционная проверка MCP через SDK-клиент с несколькими подключениями и тестовыми Telegram-адаптерами.
- Документация запуска, Dockerfile и пример Compose с постоянным томом, настройки HTTPS-прокси, примеры подключения агентов и ротации MCP-токена.
- Живой вход и отправка проверяются после предоставления серверного доступа и настройки владельцем Telegram-реквизитов. Они не заменяются тестовыми адаптерами в отчёте о проверках.
